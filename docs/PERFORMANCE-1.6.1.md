# 1.6.1 后台优化验证

同一台 Apple Silicon Mac、Java 21、512 MiB JVM 上，以相同生成数据对比 1.6.0 和本版：60 个模组、24,000 条语言文本，连续 16 批读取 / 保存；每版 5 个全新工作区，各自重新启动 JVM，下面取中位数。测量包括工作区 JSON 读写，不包括公网翻译、启动游戏和画面帧率。

| 操作 | 1.6.0 | 1.6.1 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 首次扫描 | 195.16 ms | 195.09 ms | 约 0% |
| 待译批次读取合计 | 322.11 ms | 41.39 ms | 87.2% |
| 批次保存合计 | 389.06 ms | 94.24 ms | 75.8% |

原因：行更新使用语言键索引；只重算改变资源的统计；取得足够待译条目后不再重读后续所有资源。旧工作区统计会先迁移重算，与原文相同的英文不再误报为汉化完成。首次扫描增加完成判定，未发现中位耗时回退。

其他可验证的后台行为：30 个相同简介消费者合并成一次请求；20 个相同公开元数据请求合并为一次；翻译同时最多 3 项；取消一个消费者不影响其他使用者，最后一个取消时停止对应翻译工作。元数据缓存最长 60 秒、最多 64 项 / 8 MB；翻译缓存最多 2,000 项，后台合并写盘，不含账号令牌。模组夹的清晰与磨砂层共用原图标解码结果。

保留：材质、主题、三层封面、弹窗、流体、欢迎动画、四个原始欢迎录音和界面音效。模组夹依用户要求改善薄壳与层次；没有删除动效来换取本表的耗时。测试不能代表所有实例规模、系统小版本或第三方翻译在所有网络中的响应时间。
