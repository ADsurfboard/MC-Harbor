# iOS 原生存档编辑

入口：“设置 → 存档 → 编辑存档与玩家数据”。选实例、世界及玩家后，可编辑已有的存档名称、模式、难度、极限模式、作弊、天数、当日时间、累计时间、生命、饥饿、饱和度和经验。不存在的字段不会凭空新增；未点保存不会改动存档。经验等级与进度会同步总经验，游戏模式同步已有玩家能力字段。

## 文件保护

- 与游戏、模组安装及整合包导入共用实例修改令牌，运行游戏时拒绝编辑。另取得 Minecraft `session.lock` 的 POSIX 全文件锁，兼容 Java FileChannel 锁；不截断原锁文件。
- 校验实例内路径、链接、普通文件、大小和读取长度。提交前重新核对 SHA-256 修订号与实际原件；实例或玩家切换不能复用旧修订号。
- 支持原始 NBT、GZip 和 Zlib。处理 Java modified UTF-8；只替换已有原始数据中的指定基本类型字段，不重建整个 NBT。其他字段、模组数据、数组、列表、特殊浮点位模式与根名称保留。
- 本地玩家与 UUID 对应的 playerdata 副本同步更新，UUID 与文件名不匹配时拒绝编辑。外部玩家可以单独选择；无玩家数据的世界仍可编辑世界字段。
- 先产生原始元数据 ZIP 备份，写后重新读取验证哈希，再暂存、校验并原子替换。取消或失败只恢复本次已写入、且仍与本次输出一致的文件；其他程序的新改动不会被强行覆盖。备份权限为 0600。
- 备份位于私有 Application Support 的 `harbor-world-backups`，支持原生分享。关闭 Minecraft 后，将 ZIP 内的原文件按路径放回对应世界即可手动恢复。备份仅包含本次将修改的元数据，不是区块和整个世界备份。

## 验证边界

`WorldNBTTests` 覆盖类型、压缩、截断、重复字段、深度与跨文档编辑；`WorldEditorTests` 覆盖真实文件、双玩家副本、无玩家、模式能力、失效修订、范围、链接、外进程锁与提交中取消恢复。CLT 下的 Foundation 断言不等同于 XCTest。

`test-world-nbt-interop.py` 通过真正的 Java DataOutputStream 产生全部 12 类 NBT，交给生产 WorldEditorStore 修改，再由现有 HMCL 的 NBTCodec 解码比较；同时用 Python ZIP/CRC 独立验证备份逐字节等于原件。原始、GZip、Zlib 三种格式均测试。

iPhone / iPad UI 验收使用仅存在于隔离宿主中的真实 NBT 夹具，检查保存、备份入口和重启后恢复。云端真实 SwiftUI 编译和 XCTest 尚须等待本提交的结果；这些检查不能替代进入 Minecraft 后的实玩验证。
